# Git 工作台（CC GUI 插件）

把 IntelliJ IDEA Git 工具窗口的核心工作流搬进 CC GUI：多仓库识别、本地更改、提交图、分支、合并/变基、Stash、标签、远程、子模块、Worktree、Blame、补丁与控制台。插件直接驱动本机 `git` CLI，不依赖 GitHub / GitLab API。

## 安装

1. 在 CC GUI 左侧栏打开「插件」。
2. 选择「从本地目录安装」，选中本目录（包含 `manifest.json` 与已构建的 `main.js`）。
3. 安装后在左侧栏「工作区」上方点击「Git 工作台」，打开覆盖整个应用窗口的全屏工作台弹窗。
4. 右侧面板顶部点击「图标 + Git 面板」页签进入轻量视图；面板列出当前工作区下的全部 Git 仓库（点击切换），并完整显示所选仓库的分支、变更文件（树形/平铺可切换、单链目录合并、可勾选批量暂存/取消暂存，不再截断；仓库、工作区更改、各分组、最近提交均可折叠）与最近提交；面板内的「打开全屏 Git 工作台」、提交、文件与提交历史入口会打开对应仓库的全屏弹窗。

重新安装同一目录会重新加载插件。卸载在插件管理页执行。

完整工作台不再占用中心标签页，也不受侧栏或嵌入画布宽度限制。头部提供获取 / 拉取 / 推送（带落后/领先计数）、刷新、控制台入口；点击右上角关闭图标或按 Esc 返回原界面；确认框、菜单打开时，Esc 先关闭内层浮层。关闭工作台不会清空提交草稿，也不会取消正在执行的 Git 操作。

## 开发与构建

源码是 `src/*.js` 分片，入口 `main.js` 由脚本按文件名顺序拼接：

```bash
node scripts/build.mjs
node --check main.js
```

不要直接修改 `main.js`。插件宿主只加载单文件 ESM，分片内不能使用 `import`、`require`、`eval` 或 `new Function`。

## 已实现功能

- **多仓库**：扫描工作区中的 `.git`（含嵌套仓库、worktree 的 `.git` 文件）、当前工作区父仓库、宿主已登记工作区、手动添加的仓库；侧栏统一展示分支和更改计数。发现分两阶段：先并发 `git rev-parse` 在数百毫秒内出列表，再后台一次批量目录遍历补全子仓库；结果按工作区缓存 7 天。有缓存时直接展示缓存且不自动深扫，缓存命中时不启动任何子进程；点击「重新扫描」或刷新命令才会重新扫描，缓存过期后自动重新扫描。扫描结果按 NUL 分隔，目录名含空格、中文或符号不会错位；「扫描排除」支持中文与空格目录名。扫描内置跳过 `node_modules`、`.venv`、`venv`、`__pycache__`、`.gradle`、`.next`、`.nuxt`、`.cache`、`.turbo`、`.parcel-cache`、`.svelte-kit`、`.pnpm-store`、`.yarn` 目录，不受「扫描排除」设置影响。
- **本地更改**：按「冲突 / 已暂存 / 未暂存 / 未跟踪」分组、路径筛选、树形 / 平铺切换、单链目录自动合并（`src/main/java` 显示为一行）、键盘导航（↑↓ 选择、空格暂存/取消暂存）、勾选、暂存/取消暂存、单个和整组回滚、按 hunk 或按所选行暂存/取消暂存/丢弃、重命名处理、assume-unchanged / skip-worktree 清理。
- **差异与预览**：统一 / 并排视图切换、忽略空白、上下文行数、二进制/大文件提示、64KB 输出上限提示；新文件、删除、重命名、冲突文件预览。
- **提交**：提交说明草稿与历史、主题行 50/72 字数提示；Amend、Sign-off、跳过钩子、禁用 GPG 签名、允许空提交、提交后推送收进「选项」菜单；部分 Amend 使用临时索引，不污染其它已暂存内容。
- **状态提示**：工作台内显示当前操作、引用加载失败项、引用列表因 64KB 上限截断、上游已删除。
- **提交图**：lane 拓扑图、分页、按提交说明/作者筛选、`--all`、按文件历史（`--follow`）、提交详情、变更文件列表（树形/平铺可切换，单击文件行或行尾按钮弹出差异弹窗，弹窗内可切换统一/并排视图）、提交信息/提交说明/变更文件三个区块可折叠、父提交跳转、导出补丁、Cherry-pick、Revert、Reset（soft/mixed/hard）、detached 检出、创建分支、创建标签、删除提交、压缩最近提交、修改最新提交说明。
- **分支**：本地/远程分支列表、检出、新建、重命名、删除/强制删除、合并（默认/--no-ff/--ff-only/--squash）、变基、设置/取消上游、与当前分支比较、删除远程分支；远程分支也可合并/变基。
- **Stash**：创建（含未跟踪、保留索引）、查看 diff 与文件清单、Apply/Pop/Drop、从 Stash 新建分支、清空。
- **标签**：轻量/注释标签、检出、基于标签新建分支、推送单个/全部、删除本地/远程标签。
- **远程**：添加、删除、重命名、修改 URL、Fetch、Prune、推送全部标签；Pull 支持 merge/rebase/ff-only 与 autostash；推送因远程有新提交被拒（fetch first / non-fast-forward）时按拉取策略自动拉取一次并重推，冲突则提示解决后重试（强制推送与 `--all`/`--tags` 不自动合并）。
- **子模块与 Worktree**：更新、同步 URL、添加、删除子模块；新建/删除/清理 Worktree，并可从 Worktree 列表切换仓库。
- **文件历史与 Blame**：文件历史复用提交图筛选；Blame 分段加载，点击提交查看详情。
- **补丁**：导出工作区/提交 diff；应用补丁文件（可选 `--3way`），三方应用后会取消索引写入，保留工作区改动。
- **Git 配置与控制台**：查看 `--show-origin` 配置、写入本地/全局单键；在仓库内执行任意 git 子命令并保留输出、退出码和耗时。
- **冲突**：采用 ours / theirs，或编辑后保存并标记解决；进行中的 Merge/Rebase/Cherry-pick/Revert 提供继续/跳过/中止。
- **其它**：初始化仓库、克隆仓库（可浅克隆）、添加 `.gitignore`、复制路径/哈希、提交信息历史、危险操作确认、跨平台 Windows/macOS/Linux。

## 权限

`manifest.json` 声明的能力：

- `storage` / `plugin.storage`：保存设置、提交说明历史、手动仓库。
- `theme`：注入带 `cg-` 前缀的样式，使用宿主 `var(--color-*)` token。
- `workspace.metadata.read` / `host:workspace`：读取当前工作区并登记克隆目录。
- `ui:panel-tab` / `ui:settings-section` / `ui:sidebar-entry` / `ui:overlay` / `ui:command` / `ui:workspace-menu` / `ui:file-link-menu`：注册界面入口；`ui:overlay` 承载全屏工作台与其对话框，不再申请 `ui:center-tab` 或 `ui:status-bar`。
- `exec:git` / `exec:sh` / `exec:powershell`：执行本机 git 和文件读写辅助 shell。
- `network:none`：插件自身不发网络请求；网络操作全部由 git 完成。

插件没有独立文件系统 API。文件读写通过宿主 `plugin_exec_run` 分块完成，单次输出上限 64KB。

## 限制与注意事项

- **凭据**：插件设置 `GIT_TERMINAL_PROMPT=0`、`GIT_ASKPASS=echo`，不会弹终端或保存密码。私有 HTTPS 仓库需预先配置 git credential helper；SSH 仓库需已加载 SSH agent。失败会显示 git 原始错误。
- **输出上限**：宿主单流 64KB、单命令最长 300 秒。日志每页最多 200 条，Blame 每段 250 行，diff/预览/仓库扫描超限会截断并提示；极大仓库可能需要多次分段或使用控制台。
- **文件编码**：文件预览与冲突编辑只接受 UTF-8；含 NUL 或非 UTF-8 字节（如 GBK/GB18030）的文件按二进制处理，禁用预览与写回，避免以 UTF-8 覆盖原内容。保存时先写同目录 `*.cg-tmp` 再整体替换，中途失败不会留下半截文件；POSIX 下替换前会复制原文件的权限位，`mv` 换 inode 不会丢掉可执行位。
- **排除目录只作用于未跟踪与仓库扫描**：设置页的「排除目录」按路径段、不区分大小写匹配，同时用于仓库发现遍历和未跟踪文件列表，`node_modules`、`.idea` 等目录不再计入「未跟踪」。已跟踪文件的修改不受影响——即使路径位于被排除目录下，也照常显示为「未暂存」。修改排除名单会立即重载当前工作区的仓库，无需手动刷新。
- **自动刷新的差异**：轮询发现 `git status` 签名未变时（外部反复编辑同一路径不会改变签名），会静默重取当前选中文件的差异；内容真的变化才替换缓存，未变化时界面不重渲染，不会重置已选的区块。状态签名变化时照常按代际重载全部差异。
- **内存与缓存上限**：仓库数据最多常驻 24 个，超出后淘汰最久未访问且不属于当前工作区的仓库（当前仓库与工作区内的仓库始终保留）；仓库发现缓存最多保留最近 8 个工作区，避免持久化体积随使用时间无限增长。
- **子模块状态**：`git submodule status` 的 `(describe)` 只在括号内容符合 describe 形态（commit 号、`-g<hash>`、`heads/…` 等）时剥离；路径本身以 ` (...)` 结尾（如 `vendor (old dir)`）会完整保留，不会被误切。索引里有 gitlink 但 `.gitmodules` 缺映射时 git 会直接 fatal（`no submodule mapping found`），此时改用 `git ls-files --stage` 的 mode 160000 条目重建列表，标为「未登记」，不再计为读取失败。
- **未实现 IDE 级三方合并编辑器**：冲突可通过 ours/theirs 或内置文本编辑解决，复杂重命名/删除冲突建议使用命令行。
- **交互式 rebase 编辑器未提供**：支持分支变基、压缩最近提交、删除提交、修改最新提交说明；任意提交重排/逐条编辑请使用 git CLI。
- **没有 Git LFS 专用界面**：LFS 文件仍可由 git 正常检出/提交，但插件不管理 LFS 对象。
- **Worktree**：插件不声明 `host:worktree`，Worktree 只出现在远程/Worktree 列表，切换时作为会话仓库加载；不会自动注册为宿主工作区。
- **手动仓库按宿主工作区隔离**：`manualRepos` 以工作区路径为键保存；换工作区不会串仓库。
- **部分 Amend**：使用 `GIT_INDEX_FILE` 临时索引，从 HEAD 重建后只带入勾选路径；提交完成后把真实索引中对应路径对齐到新 HEAD。
- **部分勾选提交**：同一文件的「已暂存」「未暂存」条目必须一起勾选。`git commit --only` 提交的是工作区内容，只勾其中一组会带上另一组未经审阅的改动，插件会拒绝并提示，而不是静默扩大提交范围。
- **冲突的文件级取舍**：modify/delete 冲突中某一侧没有文件版本，采用该侧等于保留删除；插件用 `git ls-files -u` 的冲突阶段号判断，缺失侧以 `git rm -f` 完成，不再对空版本执行 `checkout --ours/--theirs`。
- **部分区块暂存**：按区块暂存/取消暂存统一带 `--unidiff-zero`，`diffContext=0` 的补丁无上下文行也能应用；含无尾换行标记（`\ No newline`）的行组若与所选区块冲突（前一行被丢弃或改成上下文），整块拒绝并提示，避免 git apply 静默合并两行。
- **提交详情布局**：提交信息、提交说明、变更文件三个区块按内容顺序排列，右侧区域整体纵向滚动；三个区块都可折叠（提交信息用标题右侧箭头，提交说明与变更文件点击区块标题或按 Enter/空格），提交说明默认展开且上限为 `min(42vh, 26rem)`（旧值为 11.25rem），内容超出时在区块内部滚动；单击文件行直接打开差异弹窗（固定高度、内部滚动），不再在详情底部内嵌追加差异视图。
- **应用补丁的三方模式**：`git apply --3way` 会隐式写索引；插件在应用前拒绝与现有暂存内容重叠的文件，应用后按应用前后的索引差异取消新写入的暂存项，避免覆盖原有暂存。
- **平台**：Windows 使用 PowerShell 和本机 git；macOS/Linux 使用 `sh`。路径含空格/中文已按字面量处理；Windows 与 macOS（默认大小写不敏感文件系统）按不区分大小写比较仓库路径，Linux 保持大小写敏感；极旧 git 不支持 porcelain v2 时会退回 v1。
- **UI 主题**：样式只使用宿主 CSS token；不同 CC GUI 版本的间距和主题可能有细微差异。尺寸统一用 `rem` / `clamp()` / `min()` / 百分比并跟随宿主根字号，仅 1–3px 细线与胶囊圆角保留像素值，窗口缩放与高 DPI 下不出现固定像素挤出的横向滚动。半透明强调色用 `color-mix()`，旧 WebView 回退为宿主实色；全屏工作台层级优先用 `:has()`，不支持时由脚本给宿主覆盖层容器加类兜底。
- **全屏弹窗层级**：插件覆盖层被宿主挂在 `pointer-events:none` 的 fixed 容器里，插件内部 `z-index` 会被该容器的层叠上下文困住。插件用 `[data-plugin-overlay-host]:has(.cg-workbench-modal)` 在全屏工作台打开时把容器抬到宿主页面壳层级（z-100），因此右侧页签等宿主 chrome 不再透上来；宿主对话框（z-110）、右键菜单（z-120）与更新提示（z-105）仍在工作台之上。优先使用 `:has()`（Chromium 105+）；不支持时 `OverlayHost` 在打开工作台/对话框时直接给宿主覆盖层容器加 `cg-overlay-raised` 类，效果一致。
